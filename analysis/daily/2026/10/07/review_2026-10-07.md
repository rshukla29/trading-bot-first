## Problems found

1. **Credit-spread journal overwrites the traded contract count to 0 on a clean close.** `credit_orb_positions` row for today shows `contracts: 0`, but the log clearly shows 2 contracts traded (`SELL 777.0C/779.0C x2`, `OPENED credit spread 777.0C/779.0C x2`) and the closed-fills table confirms two round-trip legs of 1 contract each. Root cause in `run_credit_orb_bot.py:196-204`: `close_spread` decrements `pos["contracts"]` by the quantity filled on *each close attempt* and persists that running remainder via `journal.update_credit_orb_contracts(pos["id"], pos["contracts"])` (line 204) — when the position fully closes, this remainder is 0, and that 0 gets written to the same `contracts` column the facts report reads as "how many contracts were traded." This corrupts the exact sizing data the paper experiment exists to collect.
2. **The ORB "Rolling last N trades" stat has no date bound and isn't reflecting 2026-10-07.** `run_daily_review.py:130-131` runs `SELECT ... FROM orb_positions WHERE status='closed' AND symbol='SPY' ORDER BY id DESC LIMIT 20` with no date filter at all — it always reflects whatever is in the database *right now*, not "as of this report's date." Evidence: today's facts file shows "Rolling last 17 SPY ORB trades: win 35%, PF 0.44, net -3772, avg win 494, avg loss -612" — **byte-identical** to the figures already quoted in the 2026-10-05, 2026-10-06, and 2026-10-08 reviews, even though today's own trade (-1260.00, closing with `status='closed'` per the normal `close_orb_position` path) should have shifted a 20-trade rolling window. This confirms these daily reports are being generated out of chronological order (the "Open positions/orders now" tables already showed the same current-state-not-report-date behavior, flagged in the 2026-10-06 review) — but it means any "vs expectation" comparison using this line is unreliable whenever reports aren't generated same-day, which just happened here.
3. **Iron condor management failed again — now 5 for 5 reviewed days, with a different invalid strike each time.** `2026-10-07 15:46:57,948 WARNING SPY: close order for position 1 did not fill (status=Submitted) — will retry next run`, then `ERROR Error 200, reqId 200: No security definition has been found for the request, contract: Option(symbol='SPY', ... strike=816.0, right='C', ...)`. The close-fill failure recurred on 10-02, 10-05, 10-06, 10-08 and now 10-07; the invalid-strike error recurred on 10-06 (818/819), 10-08 (811/812), and now 10-07 (816) — three different wrong strikes for the same 2026-11-20 target expiry, confirming this is systematic in the strike-selection/rounding logic, not a one-off.
4. **RSI2 IBKR scanner subscription errors, recurring.** `Error 162, reqId 1824-1826: API scanner subscription cancelled`, alongside several `only N bars, strategy needs 201 — skipping` warnings (AAOX, ALMR, BSP, etc.) — same pattern flagged on 10-05 and 10-08.

Evidence: today's closed credit-spread row shows `contracts: 0` despite 2 contracts being traded, confirmed by the log and the closed-fills table (§Problems #1).
